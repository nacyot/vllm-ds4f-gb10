## 2. 첫 부팅은 효과가 0 이었다 — 입력 예산

`SHORT_RESERVE=4096` 첫 실험(`i34-sr4096-HOL1/2`)의 대기는 **64.96 / 66.73 s** 로 기준선과 같았다. 예약이 한 토큰도 물리지 않았다.

원인은 프리필 청크를 묶는 상한이 `token_budget` 이 아니라 `input_budget - draft_slots` 였다는 것이다(`scheduler.py:656` 의 `min(...)`). `draft_slots` 는 dspark 드래프터의 `max_num_new_slots_for_drafting` 로 K−1 = **4** 이고, 스케줄되는 요청마다 `input_budget` 에서 `num_new_tokens + draft_slots` 를 가져간다. MNBT 4096 에서 프리필 청크는 원래 4092 를 받아 `input_budget` 을 0 으로 만들고, 대기 루프의 `if input_budget <= draft_slots: break` 가 즉시 걸려 짧은 요청이 입장하지 못했다. 토큰 예산에서만 30 을 빼면 `min()` 이 여전히 `4096 − draft_slots` 를 고르므로 청크가 그대로였다.

고친 뒤(`_short_reserve_tokens` 가 입력 예약 = 토큰 예약 + `draft_slots × 예약 요청 수` 를 함께 돌려주고, 프리필 청크를 두 예산 모두에서 자른다) 같은 부팅 조건에서 7.01 / 8.71 s 가 나왔다.

단위 테스트 `test_short_reserve_survives_drafting_slots` 가 이 미스를 그대로 재현한다. ngram + `parallel_drafting` 이 프로덕션과 같은 K−1 슬롯을 주고, 입장 다음 스텝들에서 프리필 뒤에 선 요청이 계속 토큰을 받는지 본다. 고치기 전 코드에서 실패하고 고친 뒤 통과하는 것을 헤드에서 확인했다.

## 3. MIXLONG 은 계획대로 동률이다

`plan.md` §2 에서 미리 적은 대로다. 대기 요청은 입장 전에 프리픽스 적중을 보고하지 못해 판정이 프롬프트 길이로 이뤄지고, AG4 의 새 턴은 프롬프트가 12K 이상이라 4,096 컷오프에 걸리지 않는다. 그래서 MIXLONG 총시간은 265.0 → 265.4 s 로 사실상 그대로다(기준은 "개선"이 아니라 "+2% 이내").

다만 부분적인 효과는 보인다. MIXLONG 의 최악 TTFT 가 **72.0 → 44.4 s** 로 줄었다. 128K 프리필이 도는 동안 짧은 요청이 예산을 가져가면서 긴 턴들의 대기도 함께 짧아진 것으로 보인다.

프리픽스 적중을 미리 조회하는 2차안은 하지 않았다(`plan.md` §7 의 오너 판단 항목). 목표(HOL ≤ 15 s, 총시간 무회귀)를 1차안이 충족했고, 2차안은 KV 매니저 부작용 확인과 부팅 1회가 더 든다. 후속 이슈 감이다.

## 4. 벤치 절차

- **기준선(부팅 없음, 프로덕션 :8888)**: 외부 클라이언트 0, `num_requests_running/waiting` 0 확인 후 시작. 유휴 서버의 첫 요청은 콜드라 16K 단독이 547.9 tok/s 로 나왔고, 웜업 두 번 뒤 1,954 tok/s 로 회복한 다음 측정했다.
- **기준선에 LOGS·S128 을 추가**했다(매니저 §4 목록에는 없다). 판정 기준에 "S128 불변"과 "로짓 뒤집힘 0"이 있는데 대조군 없이는 판정할 수 없다. 둘 합쳐 2분이다.
- `mixlong.sh` 는 `--out` 을 넘기지 않아 기본 경로에 쓴다. `~/dsv41-prep/i34/mixlong_i34.sh` 사본에 `--out` 을 넣어 썼다(원본은 그대로 뒀다).
- AG4 는 `mixlong.sh` 의 AG 라인과 같은 인자로 `casebench.py --mode agent` 를 직접 불렀다.
- **부팅 3회**: ① `SHORT_RESERVE=4096` 첫 실험(효과 0) ② 수정 코드로 재실험(채택 수치) ③ 기본값 채택 후 오버라이드 없이 재기동. 단위 테스트는 ②·③ 앞의 서버 정지 창에서 돌렸다.

## 5. S128 비교에 대한 단서

기준선 S128 은 오래 떠 있던 프로덕션 서버에서 1,666.3 tok/s, 실험 S128 은 갓 부팅한 서버에서 1,792.2 tok/s 다. 부팅 상태가 달라 직접 비교가 완전하지는 않다. 다만 예약은 단독 프리필에서 코드상 0 이고(대기 요청이 없으면 `_short_reserve_tokens` 가 0 을 반환), 단위 테스트 `test_short_reserve_ignores_long_waiting_request` 가 이를 고정한다. #38 의 같은 조건 참조값 1,836 tok/s 와 비교해도 저하가 없다.
