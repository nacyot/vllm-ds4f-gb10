### #37 디코드 prefault 가 GPU 를 놀리는가

물음은 디코드 스텝마다 Engram prefault 의 CPU 작업이 GPU 를 약 10 ms 놀리느냐였다.

프로파일로 원인을 확정했다. 디코드 스텝의 Engram 페이지는 콜드 NVMe 읽기다(샤드 상주 0.1 %, 표당 72~96 페이지, 장치 22k IOPS). 러너가 해시 D2H 뒤 표 두 장을 직렬로 기다려 **스텝당 5.6 ms 가 GPU 유휴**였다. 후보 가설 중 풀 분배 비용은 약 1 ms 몫, 상주 건너뛰기는 이득 0 이었다.

`ENGRAM_DECODE_ASYNC=1`(레이어 1 표만 기다리고 레이어 14 표는 포워드 중 배경 populate)과 `ENGRAM_CHUNK_RUNS=8` 을 채택했다.

| 항목 | 부팅 0 기준선 | 채택 구성 |
| --- | ---: | ---: |
| 코드 c1 스텝 ms | 73.3 / 70.2 / 68.4 | 68.2 / 67.0 |
| 산문 c1 스텝 ms | 70.3 / 70.7 | 68.5 / 67.5 |
| DtoH 뒤 GPU 유휴 ms | 5.6 | 4.3 |
| 수락 길이(코드) | 5.82 | 5.82 |

158K 니들은 콜드 정답 "12"(TTFT 84.3 s, 1,880 tok/s), 후속 턴 정답 "986"(TTFT 0.753 s)이었다. 모드 2(표 두 장 모두 배경)는 코드가 64.6 ms 로 더 좋지만 산문에서 레이어 1 조회가 콜드 페이지를 GPU 제자리 fault 로 읽어 산문 스텝이 모드 1 보다 3.7 ms 길다. 그래서 옵트인으로 남겼다.
